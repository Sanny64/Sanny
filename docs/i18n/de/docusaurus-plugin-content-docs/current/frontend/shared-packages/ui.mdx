# @sanny/ui

`@sanny/ui` ist ein gemeinsam genutztes npm-Paket, das UI-Komponenten bereitstellt, die in allen Frontend-Projekten verwendet werden.<br/>
Es hält die übergreifenden Komponenten-Styles synchron und unterstützt gemeinsames Handling von HTTP-Fehlern und Einstellungen.

---

## Was exportiert wird

Die öffentliche API des Pakets exportiert gemeinsame UI-Komponenten sowie gemeinsame UI-Seiten, die von Frontend-Apps genutzt werden.<br/>
Zusätzlich liefert es das CSS mit, das von diesen Komponenten und Seiten verwendet wird.

- `components`
  - Standardkomponenten wie `Buttons` und `TextInputs`.
  - Erweiterte Komponenten wie das grundlegende Settings-Overlay, der Seiten-Footer und mehr, basierend auf den Standardkomponenten.
- `pages`: Vollständige Seiten, die in allen Frontend-Projekten verwendet werden, zum Beispiel `Error.tsx` und `Settings.tsx`.
- `styles`: CSS-Styles für diese gemeinsamen Komponenten und Seiten.

---

## Verwendung

Importiere in einer Seite, für die du das Routing bereits eingerichtet hast, die benötigte Komponente, zum Beispiel `Button`:

```typescript
{/* Example Hello.tsx */}
import { Button } from '@sanny/ui';
import { useTheme, getThemeVariant } from '@sanny/styles';
import { useLanguage, translations } from '@sanny/i18n';

function sayHello() {
  alert('Hello World');
}

export default function Hello() {
  const { theme, toggleTheme } = useTheme(); // nur nötig, wenn eine Komponente das globale Theme oder ihr eigenes Theme verändert.
  const themeVariant = getThemeVariant(theme); // nur nötig, wenn Komponenten ihren Stil anhand globaler Theme-Änderungen anpassen.
  const { language } = useLanguage();
  const t = translations[language]; // nur nötig, wenn Komponenten ihren Text anhand globaler Sprachänderungen anpassen.
  return (
    <div className="content">
      // Standard-Button
      <Button
        className="say-hello-button"
        aria-label="Klicken, um Hello als Alert auszugeben" // aria-label
        variant={themeVariant} // kann 'primary' oder 'secondary' sein; 'ghost' kann verwendet werden, um den Button auszublenden.
        onClick={sayHello}
      >
        Hello-World-Button
      </Button>

      // Dynamisches Rendern eines Buttons
      <Button
        className="toggle-theme-button"
        aria-label={t.shared.setupProbe.descriptionToggleThemeButton(theme)} // wechselt die Beschreibung abhängig vom Theme
        variant={themeVariant} // wechselt das Aussehen des Buttons (oder jeder anderen Komponente) abhängig vom Theme
        onClick={toggleTheme} // wechselt das Theme
      >
        {t.shared.setupProbe.toggleThemeButton(theme)} // wechselt den angezeigten Button-Text abhängig vom Theme
      </Button>
    </div>
  );
}
```

Wie üblich solltest du für `onClick`-Funktionen, die einen Parameter übergeben, ein Setup wie dieses verwenden:

```tsx
onClick={() => myFunction(parameter)}
```

Für einfache Funktionen wie `sayHello()` musst du die Funktion nicht außerhalb des Buttons auslagern:

```tsx
// Standard
onClick={() =>
  alert('Button clicked')
}

// In einem JS-Expression-Wrapper
onClick={() => {
  alert('Button clicked'); // erlaubt dir die Verwendung von Semikolons und anderer JS-spezifischer Syntax.
}}
```

Grundsätzlich ist das Auslagern von Funktionen jedoch besser für Konsistenz und Wartbarkeit.

## Hinweise für Entwickler:innen

Achte darauf, Buttons ohne ausreichend sichtbaren Kontext immer mit einem `aria-label` zu versehen, da sie häufig von Screenreadern verwendet werden.

Gemeinsame UI-Komponenten müssen routenspezifische Farbabweichungen unterstützen, ohne dabei das Layout-Verhalten zu verändern:

- Gemeinsames Komponenten-CSS liest komponentenspezifische Tokens mit globalen Fallbacks.

Das bedeutet: Wenn du gemeinsame UI-Komponenten implementierst, musst du Farbvariablen wie diese einbeziehen:

```tsx
.component--primary {
  background: var(--component-primary-bg, var(--color-primary)); // wenn `--component-primary-bg` in einer Auxiliary-Route-CSS-Datei wie `party.css` gesetzt ist, wird diese Farbe verwendet.
  color: var(--component-primary-text, white); // wenn die erste Variable nirgends gesetzt ist, fällt sie auf `var(--color-primary)` zurück.
}

.component--secondary {
  background: var(--component-secondary-bg, var(--color-surface-2));
  color: var(--component-secondary-text, var(--color-text));
}
```

Diese Tokens werden im gemeinsamen UI-Komponenten-CSS verwendet und können in Routenklassen wie `.auxiliary-layout--auxiliary-page-name` gesetzt werden:

```css
.auxiliary-layout--auxiliary-page-name {
  --auxiliary-layout-bg:
    radial-gradient(circle at top, rgba(255, 255, 255, 0.14), transparent 42%),
    linear-gradient(180deg, #0c7a00 0%, #059600 100%);
  --auxiliary-layout-text: #eff8ee;
  --component-primary-bg: #ebf8e8;
  --component-primary-text: #0d5b00;
  --component-secondary-bg: rgba(10, 79, 4, 0.45);
  --component-secondary-text: #eff8ee;
}
```

Im Gegensatz zu `Main.tsx`, das größtenteils gleich bleibt, können `Auxiliary.tsx`-Dateien je nach gerenderter Route stark voneinander abweichen:

```tsx
import { Outlet, useLocation } from "react-router-dom";
import "@sanny/styles/globals.css";
import "@sanny/styles/auxiliary.css";
import "../styles/auxiliary-pages-one-to-three.css";

export default function Layout() {
  const { pathname } = useLocation();

  function getRouteClass() {
    switch (pathname) {
      case "/auxiliary-page-1":
        return "auxiliary-layout--1";
      case "/auxiliary-page-2":
        return "auxiliary-layout--2";
      case "/auxiliary-page-3":
        return "auxiliary-layout--3";
      default:
        try {
          console.error("Unknown route:", pathname);
          return "";
        } catch (e) {
          console.error("Fehler beim Ermitteln der Routenklasse:", e);
          return "";
        }
    }
  }

  const routeClass = getRouteClass();

  return (
    <div className={`auxiliary-layout ${routeClass}`}>
      <Outlet />
    </div>
  );
}
```

Weitere Informationen zum Routenverhalten findest du [hier](/docs/frontend/projects/sanny#besonderes-verhalten).
