# Backend operations

This guide is the operator's entry point for the Fastify backend. Examples use placeholders and reserved documentation domains. Never put passwords, client secrets, private keys, certificates, access tokens, refresh tokens, or database URLs containing credentials in documentation.

## Current deployment state

The service currently runs locally with Docker; there is no hosted staging or production deployment yet. Treat local `NODE_ENV=development` checks as development verification. Running the local container with `NODE_ENV=production` only exercises production-mode configuration and headers; it is not a production deployment or staging sign-off. Create an isolated hosted staging environment before public production.

## Runtime security contract

Preserve Authorization Code Flow with PKCE, single-use OAuth state, server-side sessions, CSRF protection, recent-authentication checks for sensitive routes, validated access-token issuer/audience/signature/subject/expiry, and public-field selections that exclude `User.password`.

## Client error handling and session expiry

Fastify keeps API errors as the stable, sanitized JSON envelope. Requests that accept `text/html` (full-page browser navigations) instead receive a `303` redirect to the configured frontend origin at `/error?status=<code>`. Rate-limited API calls retain their `429` response and `Retry-After` header; browser navigations show the same status on the frontend error page.

The authenticated profile endpoint exposes the session's absolute expiry in the `X-Session-Expires-At` response header. The frontend displays an accessible warning toast 15 minutes before the fixed eight-hour session expiry, with an action to sign in again. This timestamp is based on the server-created session and is not extended by activity or token refresh.

Frontend API failures are also surfaced through accessible, dismissible toasts. Do not place provider/database diagnostics, secrets, tokens, or session identifiers in client messages or URLs.

Both the login and Sanny frontends mount the shared `ToastViewport` from `@sanny/ui`. Use its `showToast(message, { kind, durationMs, action })` and `dismissToast(id)` exports rather than adding frontend-specific notification stores. A `durationMs` of `0` keeps a notification visible until dismissed.
