# Quick Start: Testing Account Linking Locally

This guide provides step-by-step instructions to test the account linking flow on your local machine.

## Prerequisites

1. **Backend**: Node.js 18+ with npm
2. **Databases**: Redis running on localhost:6379, MySQL on localhost:3306
3. **Auth0 Setup**: An isolated development tenant and application configured according to the Auth0 tenant contract in the backend documentation.

## 1. Configure Auth0 Application

Before starting the local services, register the callback URIs in Auth0:

### In Auth0 Dashboard:

1. Go to **Applications** → Select the development application for your test environment.
2. Navigate to **Settings** tab
3. Scroll to **Application URIs** section
4. Update **Allowed Callback URLs** to include:
   ```
   https://localhost:8443/api/v001/auth/callback,
   http://localhost:5174/,
   http://localhost:5173/
   ```
5. Update **Allowed Logout URLs** to include:
   ```
   http://localhost:5173/,
   http://localhost:5174/
   ```
6. Under **Cross-Origin Authentication (CORS)**:
   - Add `http://localhost:5173`
   - Add `http://localhost:5174`
7. **Save changes**

## 2. Start Services

Open three terminal windows and run:

### Terminal 1: Backend API (port 3000)

```bash
# Run from the repository root
npm run start:backend
```

Expected output: Server starts on `https://localhost:8443`

### Terminal 2: Login Frontend (port 5174)

```bash
cd login
npm install  # if needed
npm run dev
```

Expected output: App available at `http://localhost:5174`

### Terminal 3: Main Frontend (port 5173)

```bash
cd sanny
npm install  # if needed
npm run dev
```

Expected output: App available at `http://localhost:5173`

## 3. Test Account Linking Flow

### Step 1: Create Primary Account (Email + Password)

1. Open http://localhost:5174 in your browser
2. Sign up with:
   - Email: `test+primary@example.com`
   - Password: use a unique test-only password from your password manager.
   - Username: `test_primary`
3. You should be logged in and redirected

### Step 2: Trigger Account Linking

1. Click **Logout** to log out from the primary account
2. On the login page, look for **"Continue with Google"** or another OAuth provider
3. Sign in with the **same email** (`test+primary@example.com`) using that provider
4. Auth0 detects the duplicate email and redirects you to the account linking page

### Step 3: Confirm Account Linking

You should now see the AccountLinkingPage at `http://localhost:5174/` with:

- Primary account details
- Secondary account details
- A **"Confirm Linking"** button

1. Click **"Confirm Linking"**
2. A popup opens asking you to authenticate with the secondary provider (Google)
3. Complete the authentication flow
4. After successful authentication, the popup closes
5. The accounts merge and you're redirected to the main app

### Step 4: Verify Linking Success

1. You should now be logged into the main app (http://localhost:5173).
2. Verify the account-linking result through the application's normal profile view and the isolated test database.
3. If claim inspection is required, use an approved local decoder with a non-production test token. Never paste active access, ID, or refresh tokens, cookies, or authorization codes into online tools, browser consoles, tickets, or chat.

## 4. Database Verification

To verify the database merge, use an approved read-only database client and select only non-secret fields:

```sql
-- In an isolated test database; do not select the password column.
SELECT id, email, auth0Sub, emailVerified FROM User WHERE email = 'test+primary@example.com';
-- Expect one local record after a successful link.
```

## Troubleshooting

### "Invalid redirect_uri" Error

- **Cause**: Callback URL not registered in Auth0 dashboard
- **Fix**: Re-check Auth0 Application Settings → Allowed Callback URLs
- **Verify**: `https://localhost:8443/api/v001/auth/callback` is listed

### Account Linking Page Not Appearing

- **Cause**: Secondary account email doesn't match primary account
- **Fix**: Ensure both accounts use the exact same email address
- **Debug**: Check backend logs for email mismatch messages

### Popup Window Blocked

- **Cause**: Browser blocking popups
- **Fix**: Allow popups for `localhost:5174` in browser settings
- **Check**: Look for popup notification in address bar

### "CORS Error" in Console

- **Cause**: Request origin not in `DEV_CORS_ORIGINS` in backend/.env
- **Fix**: Verify `DEV_CORS_ORIGINS` includes `http://localhost:5174` and `http://localhost:5173`.
- **Note**: Requires backend restart after .env changes

### "Redis Connection Error"

- **Cause**: Backend Redis container is unavailable or its TLS/password configuration does not match.
- **Fix**: Start the backend Docker Compose stack and inspect sanitized container health/logs. Do not substitute an unconfigured public Redis image.

### Database Connection Errors

- **Cause**: MySQL not running or credentials wrong in backend/.env
- **Fix**: Verify MySQL is running and `DATABASE_URL` in backend/.env is correct
- **Check**: Uncomment development DATABASE_URL in backend/.env if needed

## Environment Files Reference

### Backend (`backend/.env`)

```
DEV_ACCOUNT_LINK_FRONTEND_URL="http://localhost:5174/confirm-linking"  # Login UI
DEV_AUTH0_CALLBACK_URL="https://localhost:8443/api/v001/auth/callback"  # Backend callback
DEV_AUTH0_SUCCESS_REDIRECT="http://localhost:5173/"  # Main app after login
DEV_CORS_ORIGINS="http://localhost:5173,http://localhost:5174"  # CORS allowlist
```

### Login App (`login/.env.local`)

```
VITE_API_URL="https://localhost:8443"  # Backend
VITE_LOGIN_URL="http://localhost:5174"  # Self
```

### Main App (`sanny/.env.local`)

```
VITE_API_URL="https://localhost:8443"  # Backend
VITE_LOGIN_URL="http://localhost:5174"  # Login app
```
