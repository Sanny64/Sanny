# Localhost Testing Configuration for Account Linking

This document summarizes the configuration changes made to enable local development and testing of the account linking feature on localhost.

## Changes Made

### 1. Frontend Environment Configuration

#### Login App (`login/.env.local`)

Updated with clearer comments and added `VITE_LOGIN_URL` for consistency:

```env
VITE_AUTH0_DOMAIN="sanny64.eu.auth0.com"
VITE_AUTH0_CLIENT_ID="AZm6md09tLEv43byJSSkf6uLTsH9JzR0"
VITE_AUTH0_AUDIENCE="https://api.sanny64.de"
VITE_API_URL="https://localhost:8443"
VITE_LOGIN_URL="http://localhost:5174"
```

#### Main App (`sanny/.env.local`)

Updated with clearer comments and added `VITE_LOGIN_URL`:

```env
VITE_AUTH0_DOMAIN="sanny64.eu.auth0.com"
VITE_AUTH0_CLIENT_ID="AZm6md09tLEv43byJSSkf6uLTsH9JzR0"
VITE_AUTH0_AUDIENCE="https://api.sanny64.de"
VITE_API_URL="https://localhost:8443"
VITE_LOGIN_URL="http://localhost:5174"
```

### 2. Backend Configuration

#### Backend Environment (`backend/.env`)

Updated `ACCOUNT_LINK_CONFIRMATION_URL` to use localhost for development:

```env
ACCOUNT_LINK_CONFIRMATION_URL="http://localhost:5174"
```

**Note**: The existing configuration already supported localhost for:

- `AUTH0_CALLBACK_URL="https://localhost:8443/api/v001/auth/callback"`
- `AUTH0_SUCCESS_REDIRECT="http://localhost:5173/"`
- `AUTH0_LOGOUT_REDIRECT="http://localhost:5173/"`
- `CORS_ORIGINS` includes both localhost frontends

### 3. Frontend Code Changes

#### AccountLinkingPage.tsx

- Added `getCallbackUrl()` function to dynamically determine HTTP vs HTTPS based on environment
- Development: Uses `https://localhost:8443/api/v001/auth/callback`
- Production: Uses `https://` URL format
- Updated `handleConfirm()` to use the new callback URL function

This ensures the component works correctly in both development and production environments without hardcoding URLs.

## Architecture Overview

```
┌─────────────────────────────────────────────────────────────┐
│                        Auth0 Tenant                          │
│                   (sanny64.eu.auth0.com)                        │
├─────────────────────────────────────────────────────────────┤
│  Post-Login Actions:                                        │
│  • linkAccount.js (detects & redirects to linking page)    │
│  • roleClaims.js (stamps email_verified claim)             │
│  • verifyEmail.js (marks email as verified)                │
└─────────────────────────────────────────────────────────────┘
              ↓                          ↑
              │                          │
        [OAuth Code]              [/continue redirect]
              │                          │
    ┌─────────▼──────────┐  ┌───────────┴─────────┐
    │ Backend API        │  │ Login Frontend      │
    │ (localhost:3000)   │  │ (localhost:5174)    │
    │                    │  │                     │
    │ • /auth/callback   │  │ • AccountLinking    │
    │ • /account-linking │  │   Page              │
    │ • /user endpoints  │  │ • Re-auth popup     │
    └────────┬───────────┘  └───────────┬─────────┘
             │                          │
             └──────────────┬───────────┘
                            │
                   ┌────────▼────────┐
                   │ Main Frontend   │
                   │ (localhost:5173)│
                   │                 │
                   │ • User dashboard│
                   │ • Profile page  │
                   └─────────────────┘

Localhost Development Flow:
1. User logs in at localhost:5174
2. If duplicate email found, Auth0 redirects to AccountLinkingPage
3. User confirms linking + authenticates with secondary provider
4. Backend merges accounts and returns tokens with email_verified claim
5. User redirected to main app (localhost:5173)
```

## Manual Testing Suite

Before deploying to production, verify each area below against a local Auth0
tenant and backend/frontend instances.

### Account linking

- [x] Email verification works on signup (emailVerified=true in database and Auth0)
- [x] Account linking page appears for duplicate emails
- [x] Secondary authentication popup opens and completes successfully
- [x] Accounts merge correctly in the database (one record with both identities)
- [x] Failed merge attempt accounts get deleted from auth0 after 10mins (they never get written into the db)
- [x] After a google user has been deleted via the auth0 dashboard, after 60mins it is being deleted from the database. 
- [x] email_verified claim appears in tokens after linking
- [x] Users can log in with either linked credential

### Login, session, and CSRF

- [x] Login redirects through Auth0 and completes the callback with PKCE
- [x] `GET /api/v001/auth/me` reflects the authenticated identity after login
- [x] `GET /api/v001/users/me` returns the local profile (email/username) after login
- [x] Refresh flow rotates the session/refresh token without logging the user out
- [x] Logout clears session cookies and Auth0 session
- [x] Requests without a valid CSRF token are rejected on mutating routes
- [x] Sensitive routes (e.g. profile update) require a recent authentication and reject stale sessions
- [x] CORS errors do not appear in browser console

### User profile and deletion

- [x] `POST /api/v001/users/me` creates the local profile row after first login
- [x] `PATCH /api/v001/users/me` updates the username in the db and auth0 userstore
- [x] Self deletion (`DELETE /api/v001/users/me`) removes the local row and is idempotent when already absent
- [x] Admin deletion of another user (auth0|... row) removes the local row and is idempotent when already absent
- [ ] Admin role updates update auth0 users roles
- [ ] Admin PATCH username works
- [x] Deleting a `google-oauth2|...` user from the Auth0 Dashboard does **not** invoke `delete.js`; confirm the local row is instead removed by the hourly `orphaned-social-user-cleanup` job (or by triggering `cleanUpOrphanedSocialUsers()` manually in a local run)
- [ ] Admin user list pagination returns stable ordering and clamps invalid page/limit values

### Auth0 custom database scripts

- [x] `login.js` accepts correct credentials and rejects wrong password/unknown email
- [x] `create.js` rejects duplicate email/Google signups with the documented validation errors
- [ ] `verify.js` and `changePassword.js` behave per the documented callback contract
- [x] `getUser.js` returns a profile for an existing email and `callback(null)` otherwise

### Security and rate limiting

- [ ] Auth routes (`/api/v001/auth/*`) are rate limited after the configured threshold
- [ ] OTP and verification emails are not spammable by bots
- [ ] Sensitive user mutation routes are rate limited independently of auth routes
- [ ] Role sync stays disabled unless `AUTH0_ROLE_SYNC_ENABLED=true`, and only assigns configured roles
- [ ] Security logs (`logSecurityEvent`) never contain tokens, cookies, or passwords

### Quality gates

- [x] Backend logs show successful account merge
- [x] All backend tests pass (`npm run test` in `backend/`)
- [x] ESLint passes without errors
- [x] TypeScript type-check passes without errors
