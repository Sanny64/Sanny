# Monitoring and verification

## Signals and alerts

Monitor the application, NGINX, Redis, database, and Auth0 integration. Alert on:

- Fastify restarts, health-check failures, elevated 5xx responses, database connection failures, and abnormal query latency.
- Repeated `429` responses by normalized route group and Redis failures or fallback limiter use.
- OAuth initiation/callback spikes, rejected OAuth state, refresh rotation failures, and refresh-token reuse detection.
- Auth0 Management API failures and repeated divergence during account deletion.
- Failed NGINX/exporter scrapes and monitoring storage exhaustion.

Use bounded metric labels: normalized route group and status class are useful; raw URLs, query strings, user identifiers, tokens, and arbitrary input are not. Keep Prometheus and exporter endpoints private.

## Logs and privacy

Logs must not contain access/refresh tokens, session IDs, CSRF tokens, authorization codes, client secrets, database credentials, or request bodies. The configured NGINX access-log format records the URI path without its query string, but includes client IP, referrer, and user-agent. Restrict access, define retention, and assess whether referrer collection is necessary. Do not paste raw logs into tickets or chat.

Loki/Promtail and monitoring volumes are operational data stores, not public endpoints. Restrict access and retention as for application logs.

## Network exposure

- NGINX stub status listens on internal port `8081` and is restricted to the Docker network. Do not publish it on the host or expose it through the public TLS listener.
- The NGINX exporter scrapes `http://nginx:8081/nginx_status` over the private compose network.
- The compose files publish Node Exporter's port on the host; block it at the host firewall from untrusted networks or remove the host publication and scrape it internally.
- Expose Grafana/Prometheus only through the intended authenticated proxy path.
- The production compose currently maps proxy HTTP/HTTPS to host ports `8080`/`8443`. Verify and intentionally configure host-facing ports for the target platform rather than assuming standard public ports.
