# Monitoring

## Collection

Both Compose configurations run Prometheus, Grafana, Loki, and Promtail alongside the backend and NGINX. Prometheus scrapes Fastify, Redis Exporter, NGINX Exporter, Node Exporter, and itself every 15 seconds. The Redis Exporter connects to Redis over TLS with the configured CA and password; its endpoint is internal-only.

Fastify `/metrics` exports bounded HTTP request counts/latency, process metrics, Prisma operation duration and result, database/Redis probe status and duration, Redis fallback counts, refresh-token outcomes, and Auth0 Management API outcomes. Prisma labels are limited to a fixed operation name and success/failure; no SQL, parameters, identities, or tokens are exported. Database and Redis probes execute on each scrape.

Promtail ships structured Pino application logs and NGINX access/error logs to Loki. Grafana is provisioned with Prometheus and Loki data sources and the NGINX security and Node Exporter dashboards.

## Alerts and notifications

Grafana alert rules are provisioned from `backend/monitoring/alerting/rules/` and evaluated every minute.

They query NGINX logs in Loki:

- **429 Rate Limit Spike**: more than 20 logged `429` responses in five minutes; warning severity.
- **Auth Endpoint Abuse**: more than 50 requests matching the auth route in five minutes; warning severity.
- **Auth Callback Flood**: more than 20 requests matching the auth callback in five minutes; critical severity.

Each rule must remain above its threshold for two minutes. The default Grafana notification contact point is Discord; critical alerts are routed to the configured email contact point. Grafana SMTP is enabled through Compose environment variables. Verify delivery to both destinations when changing provisioning or credentials.

For local contact-point, rule-trigger, and rate-limit test procedures and recorded outcomes, see [Monitoring Integration Testing](./local-testing/monitoring-integration-testing.mdx). These opt-in tests can send real notifications and should only target the development stack.

Grafana also provisions Prometheus alerts for backend target failures/restarts, failed dependency probes, slow database probes and Prisma queries, Redis fallback use, refresh-token failures/replays, Auth0 Management API failures, missing/down exporter targets, and low host filesystem capacity. Target and storage alerts are operational signals; verify they fire and reach the configured contacts in the target environment.

The existing NGINX log-volume rules aggregate matching lines service-wide; they are coarse volume indicators, not normalized per-client attack detection or proof of an attack. Do not add client identifiers to metric labels.

## Logs and retention

Pino writes application logs to stdout and `/app/logs/app.log`; Promtail tails the file from a persistent, read-only volume. Request serializers keep only a normalized route group and bounded method, response serializers keep the status code, and error serializers omit messages and stacks. Security-audit paths have query strings removed and dynamic user routes normalized. NGINX access logs contain timestamp, method, URI path (without the query string), status, response size, and request/upstream response times; client IP, referrer, and user-agent are omitted. Do not paste raw logs into tickets or chat.

Loki uses filesystem storage with a configured retention period of seven days. Loki authentication is disabled, and its storage is operational data: keep it on the private Compose network and protect its volume and host. Prometheus, Loki, Grafana, app logs, NGINX logs, and Promtail positions use persistent Docker volumes. Backups and host-level retention/access controls remain deployment work.

Backend logs and alerts must not expose access or refresh tokens, session IDs, CSRF tokens, authorization codes, client secrets, database credentials, or request bodies. Application logging uses explicit redaction; metric labels use bounded values and never include raw URLs, query strings, user identifiers, tokens, or arbitrary request input.

## Network access

- NGINX stub status listens on port `8081` and allows only the Compose subnet. The NGINX Exporter scrapes `http://nginx:8081/nginx_status` over the internal network. Do not publish the status endpoint or expose it through the public listener.
- Backend `/metrics`, Redis Exporter, and Node Exporter are not exposed through NGINX or host-published ports. Prometheus scrapes them over the private Compose network.
- Grafana and Prometheus have no host-published ports. NGINX proxies `/grafana/` and `/prometheus/` over TLS and protects both paths with HTTP Basic Authentication.
- Both Compose files map NGINX HTTP/HTTPS to host ports `8080`/`8443`. Configure the host firewall and any external proxy deliberately for the target environment; do not assume these are standard public ports.
- Keep Loki, Prometheus, exporters, Grafana, and monitoring volumes restricted to trusted operators and the private Compose network. Monitoring endpoint authentication does not replace host/network controls.
