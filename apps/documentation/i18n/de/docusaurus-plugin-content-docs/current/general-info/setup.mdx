Klone dieses Repository, um Zugriff auf alle Anwendungen im Workspace zu erhalten. Du benötigst Node.js 24, npm 11.6.3 und Git.

## Installation und Einrichtung

Installiere alle Workspace-Abhängigkeiten im Repository-Stammverzeichnis:

```sh
npm ci
```

Wenn deine global aktive Node.js-Version von der Repository-Vorgabe abweicht, kannst du npm-Befehle mit den festgelegten Node.js- und npm-Versionen über `npx` ausführen:

```sh
npx --yes --package=node@24 --package=npm@11.6.3 -- npm ci
npx --yes --package=node@24 --package=npm@11.6.3 -- npm run test:ci
```

Verwende dasselbe Präfix auch für andere `npm`-Befehle.

Die Root-`tsconfig.json` enthält strenge, umgebungsneutrale Grundeinstellungen und Prüfungen für Repository-Tooling. Beide Frontend-Apps und die quellcodeexportierten gemeinsamen Pakete erweitern die einzige Browser-Konfiguration `apps/frontend/tsconfig.frontend.json`; gemeinsame Frontend-Umgebungsdeklarationen liegen in `apps/frontend/frontend-env.d.ts`.

Starte jede benötigte App in einem eigenen Terminal:

- `npm run dev:sanny`
- `npm run dev:auth`
- `npm run dev:docs`
- `npm run dev:docs:de`
- `npm run start:stack`
- `npm run initialize:stack` für den initialen Image-Build und den vollständigen Entwicklungs-Stack

Sanny läuft unter `https://localhost:5173`, Auth unter `https://localhost:5174` und die englische Dokumentation unter `http://localhost:3000`. Der deutsche Root-Befehl verwendet `http://localhost:3000/de/`; für einen separaten Port starte `npm run dev:de -w documentation`, das `http://localhost:3001/de/` bereitstellt. Frontend-Dev-Server verwenden ein lokales HTTPS-Zertifikat. Beende den Backend-Stack nach der Arbeit mit `npm run stop:stack`.

- `npm run format:check`
- `npm run check`
- `npm run test:ci`
- `npm run test` für das vollständige Gate einschließlich Live-Auth0-Prüfungen

## Builds

Führe vor manuellen Builds `npm run check` aus; Build-Befehle führen keine statischen Prüfungen aus.

- `npm run build:auth`, `npm run build:sanny` und `npm run build:docs` bauen einzelne Ziele; `build:docs` erstellt beide konfigurierten Sprachen. Für eine einzelne Sprache `build:docs:en` oder `build:docs:de` verwenden.
- `npm run build:frontend` baut Auth, Sanny und beide Dokumentationssprachen.
- `npm run build:backend` baut nur das Backend-Image und startet keine Services.
- `npm run initialize:stack` baut benötigte Images und erstellt den gesamten Entwicklungs-Compose-Stack neu; `npm run restart:backend` erstellt nur den Backend-Service neu. Beide erhalten Volumes.

Das Backend benötigt vor dem Start eine lokale Umgebungskonfiguration und Zertifikate; siehe [Backend-Setup](../backend/backend-setup.mdx).

## Workspace-Übersicht

- `apps/frontend/sanny/`: öffentliche React-/Vite-Website und ihre gerouteten Seiten.
- `apps/frontend/auth/`: Frontend für Account-Link-Bestätigung und Besitznachweis.
- `apps/backend/`: Fastify-API, Auth0-Skripte, Prisma-Schema, Docker Compose und Monitoring-Konfiguration.
- `shared/packages/`: `@sanny/i18n`, `@sanny/styles` und `@sanny/ui`.
- `apps/documentation/`: Docusaurus-Quellen auf Englisch und Deutsch.
- `shared/tests/`: Repository-Verträge und Playwright-End-to-End-Suites.
- `tooling/scripts/`: Workspaceweite Runtime-, Test-, Release- und Dokumentationsskripte.
- `games/`: eigenständige Spieleprojekte.
