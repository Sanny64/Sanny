# Auth

Der Workspace `apps/frontend/auth/` ist das Authentifizierungs-Frontend des Monorepos. Er verwaltet die Bestätigung von Account-Verknüpfungen, Besitznachweise und Anfragestatus, ist aber kein eigenständiges Login-Formular. Die Startseite zeigt den Anfragestatus und gemeinsame Darstellungseinstellungen; Backend-Login-Endpunkte und Auth0-Callbacks bleiben unverändert.

## Zweck

- Eine fokussierte Authentifizierungserfahrung bereitstellen
- Geschützte Abläufe von den öffentlichen Portfolio-Seiten trennen
- Sprache, Theme und UI-Verhalten mit dem Rest des Workspaces teilen
- Durch Shared Packages klein und wartbar bleiben

---

## Gemeinsame Abhängigkeiten

Die Auth-App nutzt die gemeinsamen Workspace-Packages, um mit dem Rest des Projekts konsistent zu bleiben:

- `@sanny/i18n` für Sprachverwaltung und Übersetzungen
- `@sanny/styles` für Theme und globalen Styling-Zustand
- `@sanny/ui` für wiederverwendbare Komponenten und gemeinsame UI-Muster

Auth und Sanny verwenden `AppShell`, semantische Oberflächen-Tokens für Hell und Dunkel, lokal gebündelte Manrope-Schrift und Framer-Motion-Vorgaben, die reduzierte Bewegung berücksichtigen. Gemeinsames CSS wird von `src/main.tsx` importiert, sodass auch eigenständige Proof- und Fehlerrouten dasselbe Theme erhalten.

---

## Entwicklung und Deployment

Die Befehle im Repository-Stamm sind `npm run dev:auth`, `npm run lint:auth` und `npm run build:auth`. Gezielte Accessibility-Tests laufen mit `npx playwright test shared/tests/e2e/mock/auth-accessibility.spec.ts`. Die App läuft unter `https://localhost:5174`.

Der Workflow `deploy-auth.yml` übergibt das gebaute Artefakt an den Deploy-Job und veröffentlicht `apps/frontend/auth/dist/` unter `/public_html/apps/frontend/auth/`. Der Document Root der Auth-Subdomain muss darauf zeigen. Vorhandene Laufzeitkonfigurationsdateien werden mit dem Verzeichnis übertragen; Endpunkt-URLs ändern sich nicht allein dadurch, dass der Workspace umbenannt wurde.
