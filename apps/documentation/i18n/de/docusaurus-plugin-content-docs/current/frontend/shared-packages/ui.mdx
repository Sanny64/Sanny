# @sanny/ui

`@sanny/ui` ist ein gemeinsam genutztes npm-Paket mit Benutzeroberflächen-Komponenten für alle Frontend-Projekte.<br/> Es hält die gemeinsamen Komponentenstile synchron und unterstützt eine einheitliche Behandlung von HTTP-Fehlern und Einstellungen.

`AppShell` ist der gemeinsame App-Rahmen für Sanny und Auth. Er stellt die Markenidentität, lokalisierte Sprungnavigation, einen fokussierbaren Hauptbereich, optionale `headerActions` und bewegungsreduzierte Routenübergänge bereit. Für das schmalere Auth-Layout wird `variant="auth"` verwendet. Apps importieren globale und Layout-CSS aus `@sanny/styles` im Einstiegspunkt; beachte dazu die [gemeinsame Richtlinie für Darstellung und Bewegung](./styles).

Gemeinsame Schaltflächen, Einstellungen und Toasts verwenden semantische Hell-Dunkel-Designvariablen. Die Aktionshierarchie bleibt beim Wechsel des Darstellungsthemas gleich; eine primäre Aktion darf nicht allein deshalb zu einer sekundären werden.

## Was exportiert wird

Die öffentliche API des Pakets exportiert gemeinsame UI-Komponenten sowie gemeinsame UI-Seiten, die von Frontend-Apps genutzt werden.<br/> Zusätzlich liefert es das CSS mit, das von diesen Komponenten und Seiten verwendet wird.

- `components`
  - `AppShell`, `Button`, `ButtonGroup`, `Checkbox` und `ToastViewport`.
- `pages`: Vollständige Seiten, die in allen Frontend-Projekten verwendet werden, zum Beispiel `Error.tsx` und `Settings.tsx`.
- Toast-Hilfsfunktionen: `showToast`, `showErrorToast`, `dismissToast` und `retriggerToast`.
- Komponenten-CSS liegt unter `src/styles/` des Pakets und wird von der konsumierenden App gebündelt.

## Verwendung

Importiere in einer Seite, für die du das Routing bereits eingerichtet hast, die benötigte Komponente, zum Beispiel `Button`:

```typescript
{/* Beispiel Hallo.tsx */}
import { Button } from '@sanny/ui';
import { useTheme, getThemeVariant } from '@sanny/styles';
import { useLanguage, translations } from '@sanny/i18n';

function sayHello() {
  alert('Hallo Welt');
}

export default function Hello() {
  const { theme, toggleTheme } = useTheme(); // nur nötig, wenn eine Komponente das globale Theme oder ihr eigenes Theme verändert.
  const themeVariant = getThemeVariant(theme); // nur nötig, wenn Komponenten ihren Stil anhand globaler Theme-Änderungen anpassen.
  const { language } = useLanguage();
  const t = translations[language]; // nur nötig, wenn Komponenten ihren Text anhand globaler Sprachänderungen anpassen.
  return (
    <div className="content">
      // Standardschaltfläche
      <Button
        className="say-hello-button"
        variant={themeVariant} // getThemeVariant liefert 'primary' oder 'secondary'; zusätzlich wird 'destructive' unterstützt.
        onClick={sayHello}
      >
        Hallo-Welt-Schaltfläche
      </Button>

      // Schaltfläche dynamisch darstellen
      <Button
        className="toggle-theme-button"
        aria-label={t.shared.settings.descriptionToggleThemeButton(theme)} // wechselt die Beschreibung abhängig vom Theme
        variant={themeVariant} // wechselt das Aussehen des Buttons (oder jeder anderen Komponente) abhängig vom Theme
        onClick={toggleTheme} // wechselt das Theme
      >
        {t.shared.settings.toggleThemeButton(theme)} // ändert den angezeigten Schaltflächentext passend zum Darstellungsthema
      </Button>
    </div>
  );
}
```

Wie üblich solltest du für `onClick`-Funktionen, die einen Parameter übergeben, ein Setup wie dieses verwenden:

```tsx
onClick={() => myFunction(parameter)}
```

Für einfache Funktionen wie `sayHello()` musst du die Funktion nicht außerhalb des Buttons auslagern:

```tsx
// Standard
onClick={() =>
  alert('Schaltfläche angeklickt')
}

// Innerhalb eines JavaScript-Ausdrucks
onClick={() => {
  alert('Schaltfläche angeklickt'); // ermöglicht Semikolons und weitere JavaScript-spezifische Syntax.
}}
```

Grundsätzlich ist das Auslagern von Funktionen jedoch besser für Konsistenz und Wartbarkeit.

## Hinweise für Entwickler:innen

Bevorzuge sichtbaren Button-Text und zugeordnete Formularlabels; sie stellen bereits den barrierefreien Namen bereit. Verwende ein lokalisiertes `aria-label`, wenn ein Steuerelement keinen ausreichenden sichtbaren Text hat, zum Beispiel bei einem Button, der nur ein Symbol zeigt. Verwende kein `aria-label`, das sichtbarem Text oder einem zugeordneten Label widerspricht, da es den von assistiven Technologien angesagten Namen überschreibt.

Gemeinsame UI-Komponenten verwenden die semantischen Tokens aus `@sanny/styles`. Auxiliary-Routen-Styles begrenzen derzeit nur Layout-Hintergrund und Textfarbe über `--auxiliary-layout-bg` und `--auxiliary-layout-text`; sie überschreiben keine Farben gemeinsamer Komponenten.

Setze diese Variablen in einem Routen-Stylesheet und ordne die Route in `Auxiliary.tsx` ihrer Layout-Klasse zu. Verwende für Komponenten weiterhin die gemeinsamen semantischen Tokens, statt eine API für routenspezifische Komponenten-Tokens einzuführen. Die aktuellen Routen-Styles setzen die Variablen auf Klassen wie `.auxiliary-layout--party`:

```css
.auxiliary-layout--auxiliary-page-name {
  --auxiliary-layout-bg:
    radial-gradient(circle at top, rgba(255, 255, 255, 0.14), transparent 42%),
    linear-gradient(180deg, #0c7a00 0%, #059600 100%);
  --auxiliary-layout-text: #eff8ee;
}
```

Im Gegensatz zu `Main.tsx`, das größtenteils gleich bleibt, können `Auxiliary.tsx`-Dateien je nach gerenderter Route stark voneinander abweichen:

```tsx
import { Outlet, useLocation } from 'react-router-dom';
import '@sanny/styles/globals.css';
import '@sanny/styles/auxiliary.css';
import '../styles/auxiliary-pages-one-to-three.css';

export default function Layout() {
  const { pathname } = useLocation();

  function getRouteClass() {
    switch (pathname) {
      case '/auxiliary-page-1':
        return 'auxiliary-layout--1';
      case '/auxiliary-page-2':
        return 'auxiliary-layout--2';
      case '/auxiliary-page-3':
        return 'auxiliary-layout--3';
      default:
        try {
          console.error('Unknown route:', pathname);
          return '';
        } catch (e) {
          console.error('Fehler beim Ermitteln der Routenklasse:', e);
          return '';
        }
    }
  }

  const routeClass = getRouteClass();

  return (
    <div className={`auxiliary-layout ${routeClass}`}>
      <Outlet />
    </div>
  );
}
```

Weitere Informationen zum Routenverhalten findest du [hier](/docs/frontend/projects/sanny#besonderes-verhalten).
