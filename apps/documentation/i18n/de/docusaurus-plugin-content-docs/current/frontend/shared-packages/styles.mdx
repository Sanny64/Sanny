# @sanny/styles

Sanny und Auth verwenden ein gemeinsames visuelles System. `@sanny/styles` verwaltet Theme-Zustand, semantische CSS-Variablen, lokal eingebundene Manrope-Schrift, Layout und Framer-Motion-Vorgaben. `@sanny/ui` setzt diese in Steuerelementen und `AppShell` um. Die Apps verwalten Inhalte und routenspezifische Anordnung.

## Gestaltung

Neutrale helle und dunkle Oberflächen, grüne Akzente, dezente Rahmen und Radien von 4-8px bilden die Basis. Informationen, Warnungen und Fehler erhalten eigene blaue, gelbe und rote Statusfarben. Schriftgrößen bleiben über Viewport-Breiten stabil; Layouts passen sich durch Umbruch, Abstände und begrenzte Breiten an.

---

## Theme und Speicherung

Die API exportiert `ThemeProvider`, `ThemeContext`, `useTheme`, `getThemeVariant` sowie `Theme` und `ThemeContextType`.

Der Provider prüft zuerst das `theme`-Cookie, dann localStorage und anschliessend das Systemfarbschema. Manuelle Auswahlen werden für 365 Tage gespeichert und in `html[data-theme]` sowie der Klasse `.dark` abgebildet. Ohne manuelle Auswahl folgt die App dem System. Die Umbenennung des Workspaces ändert keine Speicherschlüssel.

## Semantische Variablen

| Zweck                    | Variablen                                                                                           |
| ------------------------ | --------------------------------------------------------------------------------------------------- |
| Oberflächen              | `--bg`, `--surface`, `--surface-raised`, `--surface-muted`                                          |
| Text und Rahmen          | `--text`, `--text-h`, `--border`, `--border-strong`                                                 |
| Aktionen                 | `--accent`, `--accent-hover`, `--accent-bg`, `--accent-border`, `--on-accent`                       |
| Status                   | `--info`, `--info-bg`, `--warning`, `--warning-bg`, `--danger`, `--danger-bg`                       |
| Geometrie                | definierte Stufen von `--space-1` bis `--space-12`, `--radius-sm`, `--radius-md`, `--content-width` |
| Typografie und Animation | `--sans`, `--heading`, `--mono`, `--motion-duration`, `--motion-ease`                               |

App-Styles verwenden diese Variablen statt eigener Hell-/Dunkel-Paletten. Bestehende `--color-*`- und Button-Überschreibungen bleiben kompatibel. Party-Routen behalten ihre eigenen Farbvariablen.

## CSS-Entrypoints

- `globals.css`: Schriftdateien, Farben, Typografie, Formulare, Fokus, Reduced Motion und erzwungene Farben.
- `main.css`: gemeinsamer Rahmen, Header, responsive Geometrie und schmaleres Auth-Layout.
- `auxiliary.css`: eigenständiges Layout und Hintergrund für zusätzliche Routen.

Globale und Main-Styles werden in `src/main.tsx` importiert, damit auch Fehler- und eigenständige Proof-Routen gestaltet sind. Die Provider-Reihenfolge bleibt `ThemeProvider`, dann `LanguageProvider`.

```tsx
import '@sanny/styles/globals.css';
import '@sanny/styles/main.css';
import { AppShell } from '@sanny/ui';
import { Outlet } from 'react-router-dom';

export default function Main() {
  return (
    <AppShell variant="auth">
      <Outlet />
    </AppShell>
  );
}
```

`AppShell` bietet Branding, einen lokalisierten Skip-Link, einen fokussierbaren Main-Bereich und eine kurze Eintrittsanimation pro Pfad. Query- und Proof-Parameter starten keine neue Animation. Der optionale Slot `headerActions` nimmt app-eigene Aktionen auf, ohne Session-Logik in das gemeinsame Paket zu verschieben.

## Animationen

`ThemeProvider` umschließt untergeordnete Elemente mit `MotionConfig` mit `reducedMotion="user"` und einem 180ms-Ease-out-Übergang. Die Shell unterdrückt Eintrittsbewegungen für Nutzer mit reduzierter Bewegung. Buttons reagieren beim Drücken innerhalb von 160ms, ohne beim Hover zu wachsen oder Textschatten zu werfen. Deaktivierte Buttons haben keine Druck-Transformation.

Bei `prefers-reduced-motion: reduce` sind CSS-Animationen und Uebergänge abgeschaltet. Texte werden beim Routenwechsel nicht ausgeblendet. Button-Hintergründe wechseln ohne Farbinterpolation zwischen Themes, damit auch während des Wechsels ausreichender Kontrast besteht. Füge für dieselben Anforderungen keine separate app-eigene Motion-Konfiguration hinzu.

## Prüfung

`npm run test:ci` prüft Lint, Builds, gemeinsame Komponenten und gemockte Browser. Die Browsertests prüfen Theme-Speicherung, Kontrast, Tastaturbedienung, Reduced Motion, Schriftdateien, Desktop/Mobil und 200% Textgröße. Chromium-Baselines decken den gemeinsamen Rahmen und Auth-/Account-/Admin-Oberflächen ab. Screenreader-Tests bleiben eine manuelle Aufgabe.
