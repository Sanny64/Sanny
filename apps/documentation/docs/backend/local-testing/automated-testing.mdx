## Commands

Run commands from the repository root. For shared root-gate requirements, the latest full-run result, and common result boundaries, see the [Local Testing guide](../../general-info/testing.mdx).

| Command                               | Purpose                                                             |
| ------------------------------------- | ------------------------------------------------------------------- |
| `npm run check:backend`               | Run backend ESLint and TypeScript checks through the workspace.     |
| `npm run test:backend`                | Run backend unit, monitoring, Redis, and Discord integration tests. |
| `npm run test:unit -w backend`        | Run only backend unit tests.                                        |
| `npm run test:integration -w backend` | Run monitoring, Redis, and opt-in Discord integrations.             |

Backend-owned unit tests live in `apps/backend/src/tests/sanny64/`, grouped into `auth/`, `auth0/`, `sessions/`, `users/`, `security/`, and `observability/`. The manual proxy check lives in `sanny64/security/`. Grafana rule and Discord webhook checks, provisioning fixtures, the notification sink, and the monitoring runner belong to `apps/backend/src/tests/grafana/`. The isolated Redis runner belongs to `apps/backend/src/tests/redis/`; it runs the session-rotation tests from `sanny64/sessions/`. Cross-suite lifecycle and stale-project helpers live in `apps/backend/src/tests/`, with no catch-all scripts folder. Frontend feedback/localization contracts live in `apps/frontend/tests/`, Auth route and proof-resume tests live with the Auth app, and shared toast tests live in `shared/packages/ui/src/tests/`.

The Redis check starts a disposable Docker Compose project using `apps/backend/docker/compose/docker-compose.test.redis.yml`. It builds the Dockerfile's `builder` target, which retains backend test sources, and a Redis service without loading `apps/backend/.env` or extending runtime Compose services. The default production image instead removes `src/tests`. Its fixed test-only password is scoped to the internal Docker network. The Redis TLS configuration is shared, but the runner generates its own one-day test CA and Redis certificate in a temporary directory; it never mounts developer certificates or needs host OpenSSL. Redis must pass an authenticated TLS health check before tests start. The project uses its own network and data/log volumes, publishes no ports, and removes its containers, data volume, and temporary certificates afterward, including on failure. No running development stack is required. Redis readiness is limited to ten health-check attempts, and the test file has a 120-second timeout. `REDIS_CONNECT_TIMEOUT_MS` bounds initial session-store connections (default 10000 milliseconds).

The live Playwright suite covers Chromium, Firefox, and Edge in one invocation. Keep dedicated `TESTUSER_EMAIL` / `TESTUSER_PASSWORD` credentials for that integration suite.

Monitoring and Redis share `apps/backend/src/tests/compose-integration.mjs`: it anchors the backend directory and Compose file, disables automatic environment-file loading with `COMPOSE_DISABLE_ENV_FILE=true`, timestamps output, removes stale test projects, and always attempts teardown. Test failures take precedence over cleanup failures; interrupts return 130/143. Each suite retains ownership of fixture generation and temporary-file cleanup. `npm run test:tooling` covers the shared lifecycle without a Docker daemon.

## Test Boundaries

- **Backend:** `npm run check:backend` runs lint/types; `npm run test:unit -w backend` runs unit tests; `npm run test:integration -w backend` runs monitoring, Redis, and opt-in Discord integrations. The Redis suite uses a disposable real Redis service.
- **Frontend:** `npm run test:e2e:mocked` runs mocked browser/accessibility checks; `npm run build:frontend` builds both apps and docs. See [Frontend Automated Testing](../../frontend/local-testing/automated-testing.mdx).
- **Cross-system integration:** `node tooling/scripts/test/run-suites.mjs --live-only` exercises the connected apps, API, and live Auth0 password flow in Chromium, Firefox, and Edge in one invocation. It is not a backend-only or frontend-only gate; Google automation is intentionally skipped.

Passing backend unit, monitoring, and Redis tests does not prove every branch, production workload, or failure mode. Monitoring test rules are derived from production definitions in a temporary file; only timing is accelerated. See the [Local Testing guide](../../general-info/testing.mdx) for shared root-gate interpretation and limits.
