:::warning[Photosensitivity warning]
Live E2E tests open visible browser windows (`--headed`) and may display flashing or rapidly changing visuals. People with photosensitive epilepsy or sensitivity to flashing lights should avoid watching the browser windows while the tests run.
:::

## Commands

Run commands from the repository root. For runtime versions and shared root-gate prerequisites, see the [Local Testing guide](../../general-info/testing.mdx). Install Chromium, Firefox, WebKit, and Edge with `npx playwright install chromium firefox webkit msedge`. Mocked accessibility and route smoke tests are included in `npm run test:e2e:mocked` and additionally run WebKit; live Auth0 remains Chromium, Firefox, and Edge. Linux has its own nine Chromium screenshot baselines rather than reusing Windows images. `npm run test:visual:linux` compares them in the lockfile-matched official Playwright container; `npm run test:visual:linux -- --update` regenerates them for review. Both PR `test:ci` and the full local `npm run test` gate include this check. Docker is required. Only secret-free source is copied into the disposable workspace. The first run builds a local `sanny64-visual-deps` Docker image containing npm and Linux dependencies. Later runs reuse that image without reinstalling dependencies; changes to any copied package manifest, the lockfile (including the Playwright version), or `apps/backend/docker/Dockerfile.visual` automatically select a new image. Each run still copies fresh source into a disposable container, and normal comparisons mount the temporary source read-only. Only `--update` writes Linux snapshots back. The image build context contains only package manifests, the lockfile, and the Dockerfile, never application source or environment files. This cache is local to the Docker daemon, so fresh CI runners still perform the initial build. List cached images with `docker image ls sanny64-visual-deps` and remove unused versions with `docker image rm <image-id>`; the next run rebuilds a missing image.

| Command                                                                 | Purpose                                                                                                               |
| ----------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `npm run test:e2e:mocked`                                               | Run the mocked suite in Chromium, Firefox, and Edge; selected accessibility and Sanny route tests also run in WebKit. |
| `npm run test:visual:linux`                                             | Compare Linux Chromium visual baselines in Docker.                                                                    |
| `npx playwright test shared/tests/e2e/mock/auth-accessibility.spec.ts`  | Run only Auth accessibility specs.                                                                                    |
| `npx playwright test shared/tests/e2e/mock/sanny-accessibility.spec.ts` | Run only Sanny accessibility specs.                                                                                   |
| `npx playwright test shared/tests/e2e/mock/accessibility.spec.ts`       | Run only shared accessibility specs.                                                                                  |
| `npm run test:e2e:real`                                                 | Run live Auth0 tests in Chromium, Firefox, and Edge in one Playwright invocation.                                     |
| `npm run test:components`                                               | Run the shared UI Vitest component suite.                                                                             |
| `npm run check -w auth`                                                 | Run Auth lint and typechecking through its base scripts.                                                              |
| `npm run check -w sanny`                                                | Run Sanny lint and typechecking through its base scripts.                                                             |
| `npm run lint:auth`                                                     | Lint the Auth frontend.                                                                                               |
| `npm run lint:sanny`                                                    | Lint the public frontend.                                                                                             |
| `npm run lint -w @sanny/i18n`                                           | Lint the shared localization package.                                                                                 |
| `npm run lint -w @sanny/styles`                                         | Lint the shared styles package.                                                                                       |
| `npm run lint -w @sanny/ui`                                             | Lint the shared UI package.                                                                                           |
| `npm run build:auth`                                                    | Build Auth; run static checks separately.                                                                             |
| `npm run build:sanny`                                                   | Build Sanny; run static checks separately.                                                                            |

Each app's workspace `check` script composes its `lint` and `typecheck` base scripts; neither app exposes a test alias for lint. The mocked browser suite includes the accessibility specs; the direct Playwright commands above are useful when iterating on one suite. For shared test-gate behavior and result boundaries, see the [Local Testing guide](../../general-info/testing.mdx). See [Backend Automated Testing](../../backend/local-testing/automated-testing.mdx) for backend test coverage.

## Component Coverage

`shared/packages/ui/src/tests/component/ui-components.test.tsx` verifies shared button keyboard operation and disabled state, checkbox labeling and feedback, toast alert/status announcements and actions, language/theme persistence, and not-found content. These focused tests do not cover every prop or state combination.

## Browser Coverage

The default Playwright config selects mocked tests only. Direct live runs require `--config=shared/tests/e2e/playwright.real.config.ts`; the existing live npm scripts include it. CI rejects focused tests and cannot reuse existing dev servers. Mocked failures retain traces/screenshots; live authentication artifacts remain disabled. See [Tooling](../../general-info/tooling).

Mocked Playwright tests live in `shared/tests/e2e/mock/`. Accessibility ownership is split between `auth-accessibility.spec.ts` and `sanny-accessibility.spec.ts` and can be run with the app-specific commands above. Other specs cover route rendering/localization, apps/frontend/auth/logout controls, settings/admin UI flows, and account linking. Routed public content pages currently render translated placeholders without interactive controls; standalone Guess-the-Number and Blockrunner games are out of scope for this project's interaction tests. Mocked API responses verify frontend behavior and request/response contracts only; they do not prove backend persistence or live Auth0 behavior.

The axe tests use WCAG 2.2 AA tags across all registered Sanny public routes and the tested settings/admin states, plus Auth helper routes. App-owned accessibility specs cover English/German preference and light/dark theme combinations in Chromium, Firefox, and Edge. The shared `accessibility.spec.ts` also checks language/theme initialization in both apps and system color-scheme changes with a persisted override on Sanny Settings. These automated checks do not substitute for screen-reader testing or 200% zoom checks.

## What a Passing Run Establishes

- Frontend lint/build checks the current app and shared-package source with the configured tooling; component and mocked browser tests verify the tested UI states and request/response contracts in the configured browsers.
- Axe checks automated WCAG 2.2 AA rules only for the routes, states, languages, and themes included in the suite. Specific keyboard flows are tested, but this is not a complete keyboard audit.

Axe and browser coverage is limited to the tested rules and UI states; it does not establish complete WCAG conformance or screen-reader compatibility. Visual baselines are captured in Chromium only. See the [Local Testing guide](../../general-info/testing.mdx) for shared test-result limits and evidence guidance.
