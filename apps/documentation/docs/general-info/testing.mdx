## Root Test Gates

Run commands from the repository root with Node.js 24 and npm 11.6.3.

`npm test` in safe/full mode and `npm run test:ci` report the total test duration with start/end timestamps and the exit result. The shared stopwatch in `tooling/scripts/test/stopwatch.mjs` uses `MM:SS` or `H:MM:SS`; menu selection time is excluded. Safe mode uses the CI stopwatch without adding a second timer.

`npm test -- --help` lists the test entry points without starting tests. The menu requires an interactive terminal and rejects CI/non-terminal use with a `npm run test:ci` hint. The CI wrapper explicitly sets `CI=true`, so focused-test rejection and fresh browser servers also apply during a local CI simulation. Unknown menu, CI, suite, and visual-runner arguments fail before execution.

- `npm run test:ci` sets `NODE_ENV=development` and disables `RUN_CRITICAL_TESTS`, `RUN_429_SPIKE_E2E`, `RUN_DISCORD_INTEGRATION`, and `RUN_EMAIL_INTEGRATION`, then runs `test:core` without opening a menu. It runs formatting and static checks, repository/frontend contracts, backend and component tests, mocked browser tests, frontend and documentation builds, and Linux visual baselines. Docker and installed Playwright browsers are required; live Auth0 credentials are not.
- `npm run test` opens an interactive menu. It asks for the scope first: Safe runs `test:ci` without any API origin or environment files. Only Full asks for the API target (development or production) and then for confirmation, before it runs the core suite, live Auth0, the Discord checks (development only), and the 429 spike. `NODE_ENV` stays `development` in both cases because it only describes the in-process test runtime; the target is expressed through the API origin. The live password flow requires a reachable selected API/Auth0 tenant and dedicated `TESTUSER_EMAIL` / `TESTUSER_PASSWORD` credentials. Missing credentials are a configuration error, not a skip. Google automation is intentionally skipped because Google may block controlled browsers; an Auth0 Cloudflare challenge is an explicit manual-verification skip.
- `npm run test:unit` runs backend unit tests and Auth/Sanny/UI tests; `npm run test:contracts` runs repository and frontend contracts; `npm run test:integration` runs backend monitoring/Redis/Discord integrations; `npm run test:browser` runs mocked and documentation browser suites. Workspaces expose `test:unit` and retain `test` as an alias.
- The 429 spike is skipped unless `RUN_CRITICAL_TESTS=true` or `RUN_429_SPIKE_E2E=true`; enabling it may trigger alerts. Full enables `RUN_DISCORD_INTEGRATION` for the development target only. It sends a synthetic webhook message to `DEV_DISCORD_WEBHOOK` and verifies that the Grafana notification policy routes warning and critical alerts to `discord-alerts` (the local policy never emails), then has Grafana send a test notification through that contact point. Full also enables `RUN_EMAIL_INTEGRATION` for the development target, which sends exactly one real test email through the `email-alerts` contact point; production emails remain governed by the production policy. This check does not wait for a real firing alert. `PROD_DISCORD_WEBHOOK` is never read by tests, and production runs skip the Discord checks. The menu asks for the target only for Full scope. Only the opted-in monitoring config reads `NGINX_BASIC_AUTH_USER`, `NGINX_BASIC_AUTH_PASSWORD`, `GRAFANA_ADMIN_USER`, and `GRAFANA_ADMIN_PASSWORD`, and only the Discord checks read `DEV_DISCORD_WEBHOOK`, from `apps/backend/.env` as fallbacks through the shared allowlist helper `shared/tests/e2e/backend-environment.ts`; environment values take precedence. The NGINX pair must match an entry in `apps/backend/nginx/secret/.htpasswd`; Grafana credentials are exchanged for a session cookie. Missing or rejected credentials fail with an actionable explanation.
- The menu resolves Vite environment files independently from `apps/frontend/auth` and `apps/frontend/sanny` using each app's `loadEnv` rules. It selects `VITE_API_URL` when explicitly set, otherwise `VITE_DEV_API_URL` or `VITE_PROD_API_URL` by target, then requires both apps to resolve to the same HTTPS origin. This origin becomes `VITE_API_URL` and `E2E_API_URL` for the run. The backend-local `.env` is not used for frontend API URLs. The API URL is otherwise resolved in this order: `E2E_API_URL`, `VITE_API_URL`, then `https://localhost:8443`. The live browser server receives that origin as `VITE_API_URL`; live API requests and backend health checks use the same origin.
- `node tooling/scripts/test/run-suites.mjs --live-only`, `--monitoring-only`, and `--e2e-only` are not npm scripts. They use the same backend lifecycle manager as `npm run test` and locate npm next to the Node.js runtime when started directly with `node`. It checks `/healthcheck`, reuses a healthy backend, starts development Compose services only for an unhealthy loopback target, waits up to three minutes, and stops only services started by that command. A remote unhealthy target is never started. Create a missing stack with `npm run initialize:stack`.
- Docker test stacks (`sanny-monitoring-tests-<pid>` and `sanny-redis-tests-<pid>`) are removed when their runner finishes or is interrupted. Stacks left by a hard-killed runner are removed at the next start of that runner.

Both isolated integration runners use `apps/backend/src/tests/compose-integration.mjs` for anchored paths, timestamped output, signal handling, and unconditional teardown. Automatic Compose environment-file loading is disabled with `COMPOSE_DISABLE_ENV_FILE=true`. Temporary monitoring rules and Redis certificates are removed even when preparation or execution fails. Redis is a normal isolated integration, not a critical opt-in.

Full mode in `npm run test` enables the spike after confirmation; set `RUN_429_SPIKE_E2E=true` manually only when invoking `node tooling/scripts/test/run-suites.mjs --monitoring-only` directly:

```powershell
$env:RUN_429_SPIKE_E2E = "true"
node tooling/scripts/test/run-suites.mjs --monitoring-only
```

## Test Tiers

| Tier                                  | Root entry points                                                                                                                      | Prerequisites and boundaries                                                                                                                                                                                                                                                                 |
| ------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Unit, component, and source contracts | `test:auth`, `test:sanny`, `test:components`, `test:frontend:contracts`, `test:tooling`; backend unit tests run through `test:backend` | No live API, Auth0, or developer credentials. Backend integration portions of `test:backend` additionally require Docker.                                                                                                                                                                    |
| Isolated backend integration          | `test:backend` or its monitoring, Redis, and Discord workspace scripts                                                                 | Monitoring and Redis use disposable Docker resources; Redis tests do not load the developer environment file or require the development stack.                                                                                                                                               |
| Mocked browser                        | `test:e2e:mocked`                                                                                                                      | Installed Playwright browsers and local frontend servers; API responses are mocked, with no live backend or Auth0 credentials.                                                                                                                                                               |
| Documentation browser                 | `test:e2e:docs`                                                                                                                        | Builds and serves the documentation locally, then tests mobile Chromium; no backend or Auth0 credentials.                                                                                                                                                                                    |
| Live browser                          | `run-suites.mjs --live-only`                                                                                                           | Chromium, Firefox, Edge, network access, reachable selected API/Auth0, and dedicated password-test credentials. Only this explicitly selected config reads `TESTUSER_EMAIL` and `TESTUSER_PASSWORD` from `apps/backend/.env` as a local fallback; it does not import other backend settings. |
| Live monitoring                       | `run-suites.mjs --monitoring-only`                                                                                                     | Opt-in only; the full menu requires confirmation, Grafana credentials, and deliberate alert traffic. It can trigger alerts.                                                                                                                                                                  |

Test suites do not globally load developer `.env` files. Only the explicitly selected live Auth0 and opted-in monitoring configurations load their named credential fallbacks; CI runs `test:ci` and does not load live Auth0 credentials. Vitest uses shared jsdom defaults; only the shared UI suite loads its own setup file for cleanup. Browser configurations remain tier-specific because mocked apps, live Auth0, monitoring, and documentation have different servers and isolation needs.

Deployment contracts require the Docker Compose CLI and Bash; on Windows they use Git Bash. They execute staging and a simulated remote deployment in temporary directories and resolve production Compose with synthetic inputs, without contacting a VPS or reading real environment files. These checks run through `test:tooling` and do not require a running Docker daemon.

`test:tooling` automatically discovers `shared/tests/contracts/**/*.test.mjs`; new contracts need no package-script registration. CLI contracts simulate safe/full menu choices, production confirmation, cancellation, API mapping, child failures, and Compose teardown without live credentials. These simulations do not replace the manual safe/full acceptance runs.

## Interpreting Results

A passing gate establishes that its configured checks passed for the current checkout and local test environment. Mocked frontend tests verify UI behavior and request/response contracts, not backend persistence or live Auth0. Live authentication covers only the configured test identity and selected flows. No local gate proves behavior for every browser, device, identity provider, input, or deployment configuration, and local results are not staging or production sign-off.

Automated test coverage does not replace manual checks with other identity providers, assistive technologies, or hosted security controls. Linux visual baselines are Chromium-only. The 429 spike behavior is established only for the development stack by the latest full run; production behavior is not.

## Test Data and Evidence

Use isolated development or staging services and dedicated test identities. Never use personal accounts or record passwords, tokens, cookies, email addresses, or other personal data in test evidence. Record the date, build/revision, environment, browser/device or assistive technology, scenario, outcome, and residual issues in the restricted test record. Keep checks open until their evidence is recorded and reviewed.
