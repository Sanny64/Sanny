# Monitoring-Integrationstests

Diese Tests richten sich an den lokalen Entwicklungs-Compose-Stack. Sie können echte E-Mail- und Discord-Benachrichtigungen versenden und fügen bei Regeltests synthetische Einträge in Loki ein. Nicht gegen Produktion ausführen. Inhalte aus `backend/.env` niemals anzeigen oder committen.

## Voraussetzungen

- Entwicklungs-Stack im Repository-Stammverzeichnis mit `npm run start:backend` starten.
- In Grafana prüfen, ob die Alarmregeln unter **Alerting > Alert rules** geladen sind.
- Vor einem Trigger-Test warten, bis vorhandene 429-, Auth-Volumen- oder Callback-Flood-Alarme beendet sind.

Das Grafana-Image ist ein minimales Laufzeit-Image ohne npm. Container-Tests werden direkt mit Node und `--import=tsx` ausgeführt.

---

## E-Mail-Kontaktpunkt testen

Grafanas integrierten Kontaktpunkttest verwenden:

1. Grafana über den authentifizierten Pfad `/grafana/` öffnen.
2. **Alerting → Notification configuration → Contact points** aufrufen.
3. Den Kontaktpunkt `email-alerts` bearbeiten und **Test** auswählen.
4. Die vordefinierte Testbenachrichtigung senden und den Eingang im konfigurierten Postfach bestätigen.

Dabei wird eine echte E-Mail versendet. Zustellung und Benachrichtigungshistorie in Grafana sind der Nachweis; eine SMTP-Konfiguration allein beweist keine erfolgreiche Zustellung.

## Direkter Discord-Webhook

Den explizit aktivierten Webhooktest im Repository-Stammverzeichnis ausführen:

```powershell
docker compose --project-directory backend/docker --env-file backend/.env -f backend/docker/docker-compose.dev.yml run --rm --no-deps -e RUN_DISCORD_INTEGRATION=true sanny64-backend node --import=tsx --test monitoring/tests/discord-integration.test.ts
```

Der Test versendet eine synthetische Nachricht über die konfigurierte Webhook des Backend-Containers und erwartet HTTP `204`. Er prüft den Webhook selbst, nicht Grafanas Alarmweiterleitung. Nur ausführen, wenn eine sichtbare Testnachricht im konfigurierten Discord-Ziel in Ordnung ist.

## Grafana-Regeln auslösen

Dieser Integrationstest sendet begrenzte synthetische Loki-Einträge über die Schwellenwerte der drei Logregeln und fragt anschließend Grafana ab, ob `429 Rate Limit Spike`, `Auth Endpoint Abuse` und `Auth Callback Flood` ausgelöst wurden:

```powershell
docker compose --project-directory backend/docker --env-file backend/.env -f backend/docker/docker-compose.dev.yml run --build --rm --no-deps -e RUN_GRAFANA_ALERT_INTEGRATION=true sanny64-backend node --import=tsx --test monitoring/tests/grafana-rules.integration.test.ts
```

Dabei können Discord-Warnungen und eine kritische E-Mail versendet werden. Nur ausführen, wenn diese Nebenwirkungen beabsichtigt sind. Grafanas API-Abfrage benötigt `GRAFANA_ADMIN_USER` und `GRAFANA_ADMIN_PASSWORD`, passend zum gespeicherten Grafana-Konto. Eine Änderung der Compose-Umgebungswerte ändert kein bestehendes Grafana-Passwort; wiederholte fehlgeschlagene Basic-Authentifizierungen können das Konto vorübergehend sperren. Vor einem erneuten Versuch zuerst die Authentifizierung korrigieren.

Die synthetischen Loki-Einträge verwenden `source="integration-test"` und bleiben bis zum Ablauf der konfigurierten Aufbewahrung von sieben Tagen erhalten.

## Echten NGINX-429-Anstieg testen

Dieses separate Playwright-Szenario sendet 40 Requests über den lokalen NGINX-Proxy an `/api/v001/auth`, erwartet mehr als 20 HTTP-`429`-Antworten und wartet die Auswertungs- und Haltezeit der Alarmregel ab. Es kann den Discord-Alarm `429 Rate Limit Spike` auslösen, prüft aber weder Grafanas Status noch die Zustellung der Benachrichtigung.

In PowerShell im Repository-Stammverzeichnis:

```powershell
$env:RUN_429_SPIKE_E2E = "true"
npm run test:e2e:429-spike
```

Der Test verwendet `tests/e2e/playwright.monitoring.config.ts` und nur Chromium. Er wird von normalen E2E- und vollständigen Testläufen aufgerufen, aber übersprungen, sofern `RUN_429_SPIKE_E2E=true` nicht gesetzt ist. Setze die Variable nur, wenn der Alarm-Nebeneffekt beabsichtigt ist; zur Prüfung des ausgelösten Alarms benötigt der Test außerdem Grafana-Zugangsdaten.
