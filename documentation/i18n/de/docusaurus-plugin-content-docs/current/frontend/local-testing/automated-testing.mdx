:::warning[Warnung vor flackernden visuellen Inhalten]
Live-E2E-Tests öffnen sichtbare Browserfenster (`--headed`) und können flackernde oder schnell wechselnde visuelle Inhalte anzeigen. Personen mit photosensibler Epilepsie oder Empfindlichkeit gegenüber Lichtblitzen sollten während der Tests nicht auf die Browserfenster schauen.
:::

## Befehle

Alle Befehle im Repository-Stammverzeichnis ausführen.

| Befehl                                       | Zweck                                                                                   |
| -------------------------------------------- | --------------------------------------------------------------------------------------- |
| `npm run test:frontend`                      | App-Lint/Build, Shared-Package-Lint, UI-Komponenten und gemockte Frontend-Browsertests. |
| `npm run test:frontend:accessibility:auth`   | Nur die Accessibility-Browsertests für Auth.                                            |
| `npm run test:frontend:accessibility:sanny`  | Nur die Accessibility-Browsertests für Sanny.                                           |
| `npm run test:frontend:accessibility:shared` | Gemeinsame Accessibility-Tests in Chromium, Firefox und Edge.                           |
| `npm run test:frontend:accessibility`        | Gemeinsame und app-spezifische Accessibility-Tests in Chromium, Firefox und Edge.       |
| `npm run test:e2e:mocked`                    | Alle gemockten Frontend-Browsertests in Chromium, Firefox und Edge.                     |
| `npm run test:e2e:real`                      | Live-Auth0-Tests in Chromium, Firefox und Edge in einem Playwright-Aufruf.              |
| `npm run test:components`                    | Vitest-Komponententests für das gemeinsame UI-Paket.                                    |
| `npm run check -w auth`                      | Auth-Lint und Typprüfung über die Workspace-Basisskripte ausführen.                     |
| `npm run check -w sanny`                     | Sanny-Lint und Typprüfung über die Workspace-Basisskripte ausführen.                    |
| `npm run lint:auth`                          | Auth-Frontend linten.                                                                   |
| `npm run lint:sanny`                         | Öffentliches Frontend linten.                                                           |
| `npm run lint -w @sanny/i18n`                | Gemeinsames Lokalisierungspaket linten.                                                 |
| `npm run lint -w @sanny/styles`              | Gemeinsames Styles-Paket linten.                                                        |
| `npm run lint -w @sanny/ui`                  | Gemeinsames UI-Paket linten.                                                            |
| `npm run build:auth`                         | Auth bauen; statische Prüfungen vorher separat ausführen.                               |
| `npm run build:sanny`                        | Sanny bauen; statische Prüfungen vorher separat ausführen.                              |

Das Workspace-`check`-Skript jeder App ruft `lint` und `typecheck` auf. `npm run test:frontend` kombiniert statische Prüfungen, Builds, Komponenten und gemockte Browser inklusive Accessibility. Gemockte Tests prüfen keine Backend-Persistenz. `npm run test:ci` ergänzt Backend-Unit-, Monitoring- und Redis-Prüfungen sowie einen Docs-Build für beide Sprachen ohne Live-Zugangsdaten. `npm run test` ergänzt Live-Auth0-Integration, ohne vorherige Suites zu wiederholen. Gemockte und Live-Playwright-Suites decken jeweils Chromium, Firefox und Edge in einem Aufruf ab. Siehe [Backend Local Testing](../../backend/local-testing/automated-testing.mdx).

## Browserabdeckung

Gemockte Playwright-Tests liegen in `e2e/mock/`. Die Accessibility-Tests sind auf `auth-accessibility.spec.ts` und `sanny-accessibility.spec.ts` verteilt und mit den app-spezifischen Befehlen oben einzeln ausführbar. Weitere Specs prüfen Routen/Lokalisierung, Login/Logout, Settings/Admin und Account-Linking. Öffentliche Inhaltsseiten zeigen derzeit übersetzte Platzhalter ohne interaktive Steuerelemente; die eigenständigen Spiele Guess-the-Number und Blockrunner sind von den Interaktionstests dieses Projekts ausgenommen. Gemockte API-Antworten belegen nur Frontend-Verhalten und API-Verträge, nicht Backend-Persistenz oder Live-Auth0-Verhalten.

Axe prüft mit WCAG-2.2-AA-Tags alle registrierten öffentlichen Sanny-Routen und die getesteten Settings-/Admin-Zustände sowie die Auth-Hilfsrouten. Die app-eigenen Accessibility-Specs decken englische/deutsche Spracheinstellungen und helle/dunkle Themes in Chromium, Firefox und Edge ab. `accessibility.spec.ts` prüft zusätzlich die Initialisierung von Sprache und Theme in beiden Apps sowie System-Theme-Wechsel mit gespeicherter manueller Auswahl in den Sanny-Settings. Diese automatisierten Prüfungen ersetzen weder Screenreader-Prüfungen noch Tests bei 200% Zoom.

## Aussagekraft eines erfolgreichen Testlaufs

- Frontend-Lint/Build prüft den aktuellen App- und Shared-Package-Quellcode mit den konfigurierten Werkzeugen. Komponenten- und gemockte Browsertests prüfen die erfassten UI-Zustände sowie Request-/Response-Verträge in den konfigurierten Browsern.
- Axe prüft automatisierte WCAG-2.2-AA-Regeln nur für die in der Suite enthaltenen Routen, Zustände, Sprachen und Themes. Bestimmte Tastaturabläufe sind abgedeckt, jedoch kein vollständiges Tastatur-Audit.
- `npm run test` führt zusätzlich einen Live-Auth0-Passwort-Flow mit der konfigurierten Testidentität gegen die lokale/Entwicklungs-API und den Tenant aus. Das belegt diesen konkreten Pfad, nicht jeden Identitätsanbieter oder Kontenlebenszyklus.

Gemockte Frontend-Tests prüfen weder Backend-Persistenz noch Live-Auth0. Ein erfolgreicher Testlauf belegt nicht das Verhalten auf jedem Browser/Gerät, die Erfüllung aller WCAG-Erfolgskriterien, Screenreader-Kompatibilität, Staging-/Produktionskonfiguration oder alle möglichen Eingaben und Zustände. Visuelle Baselines werden nur in Chromium erstellt; das Root-Gate baut die Dokumentationswebsite nicht. Für die verbleibende Sicherheit sind manuelle und gehostete Umgebungsprüfungen nötig; siehe [Backend Local Testing](../../backend/local-testing/automated-testing.mdx) zu Backend- und Integrationsgrenzen.
