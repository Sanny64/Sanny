Live E2E tests open visible browser windows (`--headed`) and may display flashing or rapidly changing visuals. People with photosensitive epilepsy or sensitivity to flashing lights should avoid watching the browser windows while the tests run.
:::

## Commands

Run commands from the repository root.

| Command                                      | Purpose                                                                                    |
| -------------------------------------------- | ------------------------------------------------------------------------------------------ |
| `npm run test:frontend`                      | Run app lint/build, shared package lint, UI components, and mocked frontend browser tests. |
| `npm run test:frontend:accessibility:auth`   | Run Auth accessibility browser tests only.                                                 |
| `npm run test:frontend:accessibility:sanny`  | Run Sanny accessibility browser tests only.                                                |
| `npm run test:frontend:accessibility:shared` | Run shared accessibility checks across Chromium, Firefox, and Edge.                        |
| `npm run test:frontend:accessibility`        | Run shared and app accessibility suites across Chromium, Firefox, and Edge.                |
| `npm run test:e2e:mocked`                    | Run all mocked frontend browser tests in Chromium, Firefox, and Edge.                      |
| `npm run test:e2e:real`                      | Run live Auth0 tests in Chromium, Firefox, and Edge in one Playwright invocation.          |
| `npm run test:components`                    | Run the shared UI Vitest component suite.                                                  |
| `npm run check -w auth`                      | Run Auth lint and typechecking through its base scripts.                                   |
| `npm run check -w sanny`                     | Run Sanny lint and typechecking through its base scripts.                                  |
| `npm run lint:auth`                          | Lint the Auth frontend.                                                                    |
| `npm run lint:sanny`                         | Lint the public frontend.                                                                  |
| `npm run lint -w @sanny/i18n`                | Lint the shared localization package.                                                      |
| `npm run lint -w @sanny/styles`              | Lint the shared styles package.                                                            |
| `npm run lint -w @sanny/ui`                  | Lint the shared UI package.                                                                |
| `npm run build:auth`                         | Build Auth; run static checks separately.                                                  |
| `npm run build:sanny`                        | Build Sanny; run static checks separately.                                                 |

Each app's workspace `check` script composes its `lint` and `typecheck` base scripts; neither app exposes a test alias for lint. `npm run test:frontend` runs frontend static checks, builds, components, and mocked browsers, including accessibility specs. The complete gate runs all static checks once. Mocked tests stub API responses and do not verify backend persistence. `npm run test:ci` adds backend unit/monitoring/Redis checks and one docs build for both locales without live credentials; `npm run test` additionally runs live Auth0 integration without repeating prior suites. Mocked and live Playwright suites each cover Chromium, Firefox, and Edge in one invocation. See [Backend Local Testing](../../backend/local-testing/automated-testing.mdx).

## Browser Coverage

The default Playwright config selects mocked tests only. Direct live runs require `--config=playwright.real.config.ts`; the existing live npm scripts include it. CI rejects focused tests and cannot reuse existing dev servers. Mocked failures retain traces/screenshots; live authentication artifacts remain disabled. See [Workspace Tooling](../../general-info/workspace-tooling).

Mocked Playwright tests live in `e2e/mock/`. Accessibility ownership is split between `auth-accessibility.spec.ts` and `sanny-accessibility.spec.ts` and can be run with the app-specific commands above. Other specs cover route rendering/localization, auth/logout controls, settings/admin UI flows, and account linking. Routed public content pages currently render translated placeholders without interactive controls; standalone Guess-the-Number and Blockrunner games are out of scope for this project's interaction tests. Mocked API responses verify frontend behavior and request/response contracts only; they do not prove backend persistence or live Auth0 behavior.

The axe tests use WCAG 2.2 AA tags across all registered Sanny public routes and the tested settings/admin states, plus Auth helper routes. App-owned accessibility specs cover English/German preference and light/dark theme combinations in Chromium, Firefox, and Edge. The shared `accessibility.spec.ts` also checks language/theme initialization in both apps and system color-scheme changes with a persisted override on Sanny Settings. These automated checks do not substitute for screen-reader testing or 200% zoom checks.

## What a Passing Run Establishes

- Frontend lint/build checks the current app and shared-package source with the configured tooling; component and mocked browser tests verify the tested UI states and request/response contracts in the configured browsers.
- Axe checks automated WCAG 2.2 AA rules only for the routes, states, languages, and themes included in the suite. Specific keyboard flows are tested, but this is not a complete keyboard audit.
- The root `npm run test` also runs a live password-user Auth0 flow against the configured local/development API and tenant. This adds evidence for that test identity and path, not every identity provider or account lifecycle.

Mocked frontend tests do not exercise backend persistence or live Auth0. A passing suite does not prove behavior on every browser/device, every WCAG success criterion, screen-reader compatibility, production/staging configuration, or all possible inputs and states. Visual baselines are captured in Chromium only. Both root gates now build documentation. Use manual and hosted-environment checks for the remaining assurance; see [Backend Local Testing](../../backend/local-testing/automated-testing.mdx).
